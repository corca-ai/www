# Corca.ai 웹사이트 빌더 v0.5

> **완성된 콘텐츠는 그대로. 검색·전환·배포 가능한 웹페이지는 에이전트가.**

## 한 줄 정의

**Corca.ai 웹사이트 빌더**는 Markdown 형식의 완성된 기획서와 선언적 디자인·인터랙션 요청을 입력받아, Corca.ai의 디자인 시스템·컴포넌트·SEO·검증·배포 규칙 아래에서 반응형 웹페이지를 구현하는 **AI 기반 웹 프로덕션 에이전트**다.

영문으로는 다음 정의를 병기할 수 있다.

> **Markdown-Driven, SEO-Native Website Production Agent**

`에이전트 빌더`라는 표현도 가능하지만, 이는 “에이전트를 만들어 주는 도구”로 읽힐 여지가 있다. 외부 제품명은 **Corca.ai 웹사이트 빌더**, 내부 기술명은 **웹사이트 프로덕션 에이전트**가 가장 직관적이다.

---

## 1. 무엇을 만드는가

이 시스템은 단순히 페이지 한 장을 생성하는 도구가 아니다. Corca.ai가 앞으로 AX, 제품, 산업, 사례, 블로그, 이벤트 페이지를 늘려 갈 때 다음 흐름을 반복 가능하게 만드는 **웹페이지 생산 시스템**이다.

```text
완성 콘텐츠 + 선언적 디자인 요청
                ↓
콘텐츠 구조화 · 페이지 계약 · SEO 설계
                ↓
Corca 디자인 시스템 기반의 반응형 구현
                ↓
성능 · 접근성 · 콘텐츠 일치 · SEO 검증
                ↓
Diff · PR · 배포 승인 · 실서비스 반영
```

사용자는 Figma를 먼저 만들지 않아도 된다. 대신 사람이 읽기 좋은 기획서를 AI가 구현하기 좋은 구조로 제공한다. 에이전트는 그 기획서의 의미 구조를 읽고, 기존 Corca.ai 웹사이트의 컴포넌트와 디자인 언어를 조합해 실서비스 수준의 페이지를 만든다.

## 2. 핵심 원칙

### 2.1 콘텐츠는 고정하고, 구현을 자동화한다

이 시스템은 사용자가 제공한 완성 콘텐츠를 임의로 다시 쓰는 카피 생성기가 아니다.

- 원문 문구, 수치, 고유명사, 주장, CTA는 콘텐츠 원본을 기준으로 유지한다.
- Markdown의 `H1`, `H2`, `H3`, 본문, 목록, 주석, CTA 구조를 웹의 의미론적 마크업으로 변환한다.
- 내용이 모호하거나 구조가 부족한 경우에는 문장을 추측해 바꾸기보다, 콘텐츠 계약의 빈칸으로 남기거나 확인 절차를 둔다.
- PDF를 입력으로 받는 경우에도 먼저 원문 대조용 콘텐츠 레저(Content Ledger)를 만들고, 원본과 100% 일치하는지 검증한 뒤 구현한다.

핵심은 간단하다. **콘텐츠의 소유권은 사람에게, 구현의 반복 작업은 에이전트에게 둔다.**

### 2.2 디자인은 화면이 아니라 선언으로 전달한다

Figma의 픽셀 좌표 대신, 페이지가 전달해야 할 우선순위와 관계를 선언한다.

예를 들면 다음과 같다.

```md
- Hero: 가장 큰 문제를 한 문장으로 제시한다.
- Proof: 문제의 구조를 비교 다이어그램으로 보여 준다.
- CTA: 기존 AX 상담 신청 폼으로 연결한다.
- Motion: 배경은 조용히 움직이고, 본문 가독성을 침범하지 않는다.
- Tone: Apple 제품 페이지처럼 절제되고, Corca의 블루와 Pretendard를 유지한다.
```

에이전트는 이 선언을 레이아웃, 간격, 타이포그래피, 카드, 배경, 인터랙션, 반응형 규칙으로 번역한다. 이것이 **선언적 디자인(Declarative Design)** 기반의 웹 제작 방식이다.

### 2.3 기존의 검증된 컴포넌트는 유지한다

신규 페이지가 늘어날수록 공통 영역을 매번 새로 만들면 브랜드와 전환 흐름이 흔들린다. 따라서 다음은 공유 컴포넌트 계약으로 유지한다.

- GNB와 언어 선택기
- Breadcrumb
- Footer
- Lead Form과 상담 신청 CTA
- 공통 폰트, 색상 토큰, 반응형 브레이크포인트
- 공통 SEO 메타데이터와 구조화 데이터 규칙

새 페이지는 이 기반 위에 **중간 콘텐츠 섹션만 목적에 맞게 조합**한다. 페이지가 달라져도 Corca.ai라는 하나의 서비스 안에서 만들어진 경험으로 느껴져야 한다.

### 2.4 SEO는 마지막 태그 작업이 아니라 정보 구조다

SEO는 title과 description만 넣는 일이 아니다. 이 시스템은 기획 단계부터 검색 엔진과 사람 모두가 페이지를 이해할 수 있도록 설계한다.

- 한 페이지에 하나의 검색 의도와 명확한 `H1`
- 논리적으로 이어지는 `H2`, `H3`, 본문 구조
- 페이지 목적에 맞는 URL slug와 내부 링크
- title, meta description, canonical, robots 정책
- 다국어 확장 시 locale URL과 `hreflang` 계약
- 서비스·FAQ·Article 등 페이지 성격에 맞는 구조화 데이터 검토
- 이미지 대체 텍스트, 링크 문구, 의미론적 landmark
- 성능과 Core Web Vitals를 해치지 않는 인터랙션

검색 노출은 페이지 수를 늘린다고 자동으로 생기지 않는다. **명확한 검색 의도, 독자에게 실제로 도움이 되는 원문, 일관된 정보 구조, 기술적으로 건강한 구현**이 함께 있어야 한다.

### 2.5 자동화에도 승인 경계는 둔다

에이전트는 구현과 검증을 최대한 자동화할 수 있지만, 실서비스에 영향을 주는 행위에는 명시적 경계를 둔다.

```text
구현 → 로컬 미리보기 → 자동 검증 → Diff 검토 → Commit/PR → 배포 승인 → 실서비스 반영
```

- 로컬 구현, 정적 분석, 빌드, 성능·SEO 검사는 자동화 범위다.
- Diff는 사람이 변경 의도를 빠르게 검토할 수 있는 형태로 남긴다.
- Commit, Push, PR, 프로덕션 배포는 팀의 승인 규칙에 따라 반자동 또는 자동화한다.
- 원문과 다른 콘텐츠, 예상하지 못한 라우트, 공통 컴포넌트 변경은 별도 검토 대상으로 올린다.

속도는 높이되, 서비스 품질과 통제권은 잃지 않는 방식이다.

## 3. 입력: 에이전트에게 무엇을 주는가

### 필수 입력 — 콘텐츠 기획서

Markdown 또는 Notion 문서에 아래 구조를 담는다.

```md
# 페이지 제목 / H1

## 페이지 목표
- 검색에서 사용자가 이해해야 할 것
- 방문자가 취한 뒤 기대하는 행동

## SEO 메타데이터
- title
- description
- URL slug
- 핵심 키워드

## 섹션 콘텐츠
### Hero
### Problem
### Proof
### Solution
### CTA
```

### 선택 입력 — 선언적 디자인과 인터랙션

- 참고할 페이지 또는 브랜드 톤
- 강조할 문장과 정보 우선순위
- 카드, 비교표, 타임라인, 다이어그램 등 원하는 정보 표현 방식
- 배경 효과, 스크롤 reveal, 모션 속도, reduced-motion 대응
- 데스크톱·모바일에서 반드시 지켜야 하는 레이아웃 의도
- Lead Form 연결 위치와 CTA 문구

### 시스템이 해석하는 컨텍스트

- Corca.ai의 기존 컴포넌트와 디자인 토큰
- Astro 기반의 라우팅·빌드 구조
- SEO 및 콘텐츠 거버넌스 문서
- URL, 다국어, 배포, Diff/PR 규칙
- 기존 페이지의 검증 방식과 품질 기준

## 5. Ceal 페이지: v0.5 검증 사례

`/ax/ceal` 페이지는 이 방식의 첫 검증 사례다. 약 3시간의 집중 구현 동안 PDF/Markdown 기반 콘텐츠를 웹페이지로 옮기고, 실제 화면 피드백을 반영해 디테일까지 다듬었다.

### 구현한 범위

- 기존 Corca.ai GNB, Footer, Breadcrumb, Lead Form 흐름을 유지
- Ceal의 문제·아키텍처·효과·도입 프로세스·차별점·CTA를 독립 섹션으로 구현
- Apple 제품 페이지의 절제된 밀도와 Corca의 블루·Pretendard 디자인 언어 결합
- 비교 다이어그램, 프로세스 카드, 정보 계층, 카드 간격을 화면 피드백으로 반복 조정
- Vanta Rings 기반 배경 인터랙션을 Corca 색상으로 조정하고, 읽기 어려움이 생기지 않도록 대비·속도·fallback을 제어
- 데스크톱과 모바일에서 콘텐츠 우선순위가 유지되도록 반응형 조정
- 콘텐츠 원문과 구현 결과를 대조할 수 있는 콘텐츠 정본과 자동 검증 계약 작성

### 이 사례가 증명한 것

Ceal은 “AI가 그럴듯한 화면을 한 번 생성한 결과”가 아니다. 콘텐츠 계약, 기존 디자인 시스템, 현장 피드백, 코드 검수, 빌드 검증이 함께 작동한 결과다.

그래서 결과물은 흔히 말하는 AI Slop—맥락 없이 화려한 장식, 과도한 그라데이션, 무의미한 카드 반복, 반응형에서 무너지는 레이아웃—과 거리가 있다. 페이지의 모든 요소는 콘텐츠를 더 잘 이해시키거나, 신뢰를 높이거나, 다음 행동을 돕기 위해 존재한다.

- 코드 스타일, 타입, 정적 검사, 빌드 검사
- 성능·SEO·에이전트 탐색성 검증 스크립트

- PR과 배포 전 변경 근거를 남기는 운영 흐름

## 7. Lead Form과 전환 추적의 역할

SEO의 목적은 단순 노출이 아니라 적합한 가망고객을 만나는 것이다. 신규 페이지가 계속 늘어나면 “어느 페이지가 상담 신청을 만들었는가”를 알 수 있어야 한다.

따라서 Lead Form에는 다음의 locale-neutral 선언과 실제 제출 경로를 공통 흐름으로
결합하는 계약이 필요하다.

```text
page_id            언어와 무관한 페이지 식별자
content_type       콘텐츠 유형
page_path          실제 폼 제출 페이지 경로
base_path          locale을 제외한 기준 경로
locale             제출 시점의 언어
```

최초 랜딩 경로, 외부 referrer hostname과 UTM은 별도의 비식별 acquisition context로
수집한다. 이 계약이 있으면 AX 하위 페이지, 블로그, 제품 페이지가 같은 Lead Form을
재사용해도 어떤 콘텐츠가 실제 리드를 만들었는지 분석할 수 있다.

## 8. 다국어 확장 방식

한글 페이지를 단순 번역해 붙이는 방식으로는 검색 품질을 유지하기 어렵다. 다국어 페이지는 같은 정보 구조를 공유하되, 각 언어의 검색 의도와 메타데이터를 독립적으로 검수해야 한다.

```text
/ax/ceal       한국어
/en/ax/ceal    영어
/ja/ax/ceal    일본어
/zh/ax/ceal    중국어
```

확장 시에는 다음을 함께 관리한다.

- 언어별 원문 콘텐츠와 번역 승인 상태
- locale별 title, description, URL slug
- `hreflang`과 canonical 관계
- 언어 전환 UI와 내부 링크
- 페이지별 CTA·Lead Form 출처 값
- 한 언어만 미완성일 때의 인덱싱 정책

## 9. 앞으로의 버전 방향

### v0.6 — 페이지 계약을 표준화한다

## 10. 최종 포지셔닝 문구

### 제품 소개용

> **Corca.ai 웹사이트 빌더는 완성된 Markdown 기획서와 선언적 디자인 명세를 SEO 최적화·다국어·반응형·전환 추적이 가능한 실서비스 웹페이지로 구현하고 검증·배포하는 AI 기반 페이지 생산 시스템입니다.**

### 더 짧은 소개용

### 팀 내부 정의용

> **콘텐츠는 사람이 결정하고, 에이전트는 Corca의 웹 규칙 아래 구현·검증·배포를 반복한다.**
